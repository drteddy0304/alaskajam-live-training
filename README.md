# Alaska Jam LIVE TRAINING

縦画面スマホでライブのアクションを練習する静的Webアプリ。
2026/12/2 渋谷CLUB QUATTROへの導線を想定したMVPです。公演日・会場は依頼時の指定情報です。チケットURLは未指定のため、架空のリンクは設けていません。

## MVP

- QUATTRO参戦予習のセットリストはCAT WALK LIFEとSNACK SNACKの2曲。CAT WALK LIFEは約3分44秒のフル尺版、SNACK SNACKは準備中。
- 提供されたCAT WALK LIFE.mp3を最後まで再生。公式Cheering Guideとユーザーの実演記録を反映しています。現在の採点譜面はCLAP 102件・WIPER 96件・タップCALL 30件です。
- 音あり練習は開始タップで曲を再生、1.8秒前から予告、タイミングバー、PERFECT / GOOD / MISS。
- CLAP / CALL / JUMP = 中央パッドをタップ。WIPER = 指示方向の左右専用ボタンをタップ。
- CALLの声やJUMPの実動作は任意。マイク・カメラ・位置情報は一切使用しません。
- 冒頭の「AJ!」は27.973秒で1回、2Aの「1 2 3」は104.785 / 105.036 / 105.322秒で3回、それぞれタップ＋発声のCALLとして採点します。
- 一時停止・再開・画面非表示時の自動停止・リトライ。練習中はシークバーと±10秒ボタンで任意の位置へ移動でき、移動前のノーツは部分練習の採点対象から除外します。音源・譜面・歌詞・公式動画を同じ位置へ合わせます。
- 曲の再生位置だけから予告・歌唱中・終了を決める客席コール表示。2周目に記録した68件の発声マーカーを使い、2秒前から予告します。ラストサビ2・3周目の24件はタップ＋声のCALLとして採点し、それ以外の重複CALLは表示だけなので二重加点しません。
- 右から左へ流れる、文字・記号・色で区別したアクションノーツ。左側の固定AJ判定位置で従来どおりタップ／左右スワイプします。
- 練習画面上部で公式YouTubeガイドをON/OFF可能。字幕OFF・公式コントロール付き・ミュート・インライン再生で、確認済みの8.2508秒差に合わせて開始・再開します。再生中はMP3位置を正本として実測し、0.75秒を超えるずれだけを開始10秒までは2秒間隔、その後は8秒間隔で、読込済み区間内に限って補正します。動画が停止・広告・読み込み中・失敗の場合もMP3によるゲームは継続します。
- 結果の主役は「QUATTRO参戦準備度」。同じ端末にベストのみ保存。保存不可でもプレイ可能。
- 開始タップ直後から動画やゲームより手前の全画面に実時間の「5、4、3、2、1」を表示し、同じタップ処理内でMP3とYouTubeの両方に再生を要求してスマホ向けにアンロックし、同期開始位置へ停止・リセットします。5秒とメディア準備の両方が完了した時だけ一緒に再開し、準備が長い場合は準備中表示を維持します。カウント中は進捗を0に保ち、パッドと採点を無効にします。動画OFF・ブロック・失敗時もMP3ゲームは継続します。MP3は約7.2MB。練習は224.39秒で終了。
- ログイン・DB・有料API・外部フォント・独自計測・ランタイム依存なし。お手本は公式YouTubeへのリンクで開きます。
- `recorder.html`は曲を再生しながら、CLAP / CALL / CLAP＋CALL / JUMP / WIPER左 / WIPER右それぞれの専用ボタンを押した瞬間の音源時刻へ直接記録します。キーボードではSpaceでCLAP、←／→でWIPERを押した瞬間に記録し、キーリピートは無視します。種類の選択、共通パッド、スワイプ判定はなく、短い間隔の異なる動作も続けて入力できます。同時操作はCALLへ`simultaneous: ["CLAP"]`を、WIPERは`direction`へ左右を明示します。途中停止・再開、直前の1件取消に加え、5秒戻して停止し、その地点以降の記録を消して録り直せます。曲終了後は前の記録を残したまま次の周を追加でき、各ノートの`pass`と全体の`passes`に周回情報を保存します。端末内の自動保存、JSONコピーに対応します。記録は外部へ自動送信しません。
- 記録専用音源には実際の無音5秒を先頭へ追加し、その区間で「5、4、3、2、1」を表示します。端末のミュート仕様へ依存せず、1の後に曲頭と記録時刻0秒が一致します。通常ゲームの音源は変更しません。

## 操作・採点

バーが満ちる時刻に、黒いアクションパッドで指を離します。
タップは移動20px未満・400ms未満。スワイプは横36px以上、縦移動の1.3倍超、800ms未満。
PCはSpace、左右矢印キー。Escapeで一時停止。

PERFECTは±0.12秒、GOODは±0.22秒。それを過ぎたノートや判定範囲内の違う操作はMISS。密なリズムでは判定範囲内のうち入力種別が一致する最も近いノートを判定します。
判定範囲より早い操作はノートを消費しません。同じノートへの二重加点はありません。
準備度 = round((PERFECT数 + GOOD数 × 0.7) / 全ノート数 × 100)。実ライブの習熟度評価ではありません。

## 公式Cheering Guide・権利処理済み音源への差し替え

1. **公式Cheering Guideを正本**として、対象曲・版・出典URL・秒単位の動作を確認する。推測で公式譜面を作らない。
2. `data/demo.json`を複製して曲ごとのJSONを作る。`id`は曲と譜面改訂ごとに新しくする（ベスト記録を混ぜない）。
3. `source.name / url / revision`に正本と版を記録。全動作と時刻を確認してから`kind`を`official`にする。各`notes`は時刻順の`{ "time": 12.5, "action": "CLAP" }`形式。WIPERには`"direction": "left"`または`"right"`を必須とする。
4. `duration`を秒数で指定し、最後のノートの0.22秒後以降にする。`leadTime`は予告秒数。現在のエンジンは時刻順の単一採点アクションを扱い、密なリズムでは入力種別が一致する最も近いノートを優先する。声だけCALLは歌詞データの`markers`へ置き、採点ノーツには加えない。
5. 配信許諾を確認した音源だけを`assets/audio/`へ追加。`audio`を`{ "src": "./assets/audio/example.mp3", "offset": 0 }`へ変更。`offset`は譜面の0秒に相当する音源側の開始秒（0以上）。音声プレーヤーのcurrentTimeを判定時計に使い、停止・再開・読み込み待ちも連動する。
6. `data/songs.json`の該当曲へ`chart`パスを追加し、`status`を`ready`へ変更すると選択できる。ホーム・結果・フッターの体験版表記も正式な公開内容に合わせて更新する。初回体験ボタンは最後に読み込んだ譜面を再生する。
7. 正式な公演・チケットURLを確認後、ホームと結果の公演欄にリンクを設ける。

### スマホ再生修正（mobile1）

AudioContextからHTMLAudioElementへ変更。play()は開始タップ内で、譜面取得などの非同期処理より前に呼び出す。対応端末ではAudio Sessionをplaybackに設定。30秒の読み込みタイムアウトを設け、再生拒否は開始画面へ戻して通知する。端末のメディア音量や出力先はアプリから変更できない。iPhone実機での出力確認はユーザーの再試行待ち。
